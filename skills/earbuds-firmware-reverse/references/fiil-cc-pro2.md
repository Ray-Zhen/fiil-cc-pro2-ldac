# FIIL CC Pro2 离线激活的技术过程

通过反编译 FIIL+ 定位蓝牙指令，再从耳机读出固件分析指令的处理逻辑。**本地激活分支是在耳机主控固件里找到的。** 以下过程实测于国行 F039，固件 `1.0.1.0`。

1. **从 App 找到激活相关指令。** 追踪 FIIL+ 的 LDAC 页面刷新和蓝牙收发代码，找到查询两耳激活状态的 GAIA 指令 `0x07AF`，以及写入激活数据的 `0x07B0`。早期测试中，向普通写入分支提交全零数据能收到成功应答，但用 `0x07AF` 查回仍是未激活。
2. **从实机只读导出固件。** 通过 Windows 蓝牙连上耳机，从 APK 找到 Airoha 的 RFCOMM 服务。用 RACE `0x0403` 读出 Flash 分区表，再按分区范围读取主控程序。主控镜像从 `0x08133000` 开始，按这个地址载入并以 ARM Thumb 反汇编。
3. **在固件里找到本地激活分支。** 沿 `0x07B0` 的处理逻辑追到 `0x081C1840`，看到它会检查一种两字节载荷 `<耳侧选择器> 88`。指定本耳时，处理函数自行计算该耳的 16 字节激活值，写入设备存储项 `0xFA01`。指定另一耳时，指令会转发过去。查询指令 `0x07AF` 会重新计算期望值，并与该存储项比较。这解释了为什么写入成功应答本身无法证明已激活。
4. **逐耳验证，再开启 LDAC。** 给两耳各发一次两字节激活指令，每次都用 `0x07AF` 确认该耳从 `0` 变为 `1`。随后用 `0x07B2` 开启 LDAC，用 `0x07B3` 确认开关为 `1`。连回小米 14 后，FIIL+ 显示开关已开启、状态为「高清」。

最终脚本把逐耳激活、状态回读和开关确认串成一个命令。这个案例说明了如何从 App 指令追到设备固件，再验证本地处理分支。其他型号和版本需要重新核对。
